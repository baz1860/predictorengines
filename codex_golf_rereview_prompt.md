## Claimed fixes to attack

### 1. Event identity, live state, and odds provenance

Attempt to make the engine price event B using event A's leaderboard or odds.

- Test matching and mismatching `event_id` and normalized event names independently.
- Test blank IDs, blank names, renamed events, simultaneous events, copied files, touched files, malformed timestamps, future timestamps, timezone offsets, and old content rewritten with a new mtime.
- Test field refresh success followed by leaderboard, weather, Bovada, or Odds API failure.
- Test whether stale `scores_live.csv`, `live_state.json`, `predictions_inplay.csv`, `odds.csv`, `matchups.csv`, or round-group files survive any failure path.
- Confirm all odds producers—not only Bovada—write an event tag and content capture time.
- Confirm pre-tournament and in-play paths both reject missing, malformed, or mismatched provenance.
- Check whether manual files can bypass the guard through mixed event tags across rows.

### 2. Point-in-time validation and calibration

Prove whether historical predictions can still read present-day information.

- Trace public PGA stats, global priors, OWGR, course architecture, course history, weather, tee times, aliases, model config, sim config, and calibration through every validation/tuning path.
- Test `walk_forward`, `tune_config`, `sweep_win_corr`, ablations, calibration fitting, and any alternate validation entry point separately.
- Place an extreme current-only prior in each current snapshot file and demonstrate whether a 2023/2024 prediction changes.
- Verify historical features are disabled by executable flags rather than comments.
- Verify `point_in_time_safe` cannot be forged merely by loading an old CSV and adding a column.
- Verify legacy calibration and baseline files are rejected, while current versioned files are accepted.
- Confirm the current `validation_baseline.json` and `calibration.json` were generated by the corrected path rather than hand-labelled.
- Recompute the reported 18,873 player-events, 131 events, and headline Brier `0.12932` if practical. Explain any difference.

### 3. Hyperparameter selection and regression gate

- Verify tuning, selection, promotion, and final reporting use genuinely disjoint temporal windows.
- Check every fallback when one window is empty. No code may silently fall back to the full dataset.
- Quantify Monte Carlo noise relative to promotion thresholds.
- Confirm the win-correlation candidate is selected before and independently tested on the final holdout.
- Confirm `golf/update.sh` validates before replacing the live model, stops on gate failure, does not recalibrate after failure, and cannot continue because of shell error-handling mistakes.
- Confirm the baseline changes only through an explicit promotion command and cannot ratchet during ordinary gate runs.
- Test interruption between validation, refit, and calibration. Determine whether the live artifacts can end in an internally inconsistent version set.

### 4. Manual 2-ball/3-ball parsing

Fuzz the parser and require malformed groups to fail closed with a visible QA warning.

Include:

- a missing first, middle, or final price;
- a missing first, middle, or final player;
- promo lines such as `Was 3.10`, boosted prices, each-way text, and market rules;
- wrapped names and headers;
- decimal, fractional, American, evens, malformed, zero, negative, NaN, and infinite odds;
- duplicate players or prices;
- a 3-ball header with two selections and a 2-ball header with three;
- headers containing surnames while selections contain full names;
- explicit tie/draw selections;
- mixed rounds and events in one paste;
- Unicode whitespace, accents, apostrophes, hyphens, initials, and suffixes.

Confirm rejected groups cannot remain in an older parsed CSV and be priced after the new paste fails.

### 5. No-cut, cut, shortened-event, WD, and DQ behavior

- Trace `cut_rule`, `no_cut`, and total-round count from ESPN payload → event object → SQLite → `field.csv`/live state → season/engine → both simulators → edge suppression.
- Test a 72-player no-cut event, a field of exactly 65, a field of 66, a standard top-65-and-ties cut, a secondary cut, and a cut-rule change.
- Test no-cut metadata that is missing, false, string-valued, malformed, or changes after the event begins.
- Test 54-hole and weather-shortened events both before and after the shortening announcement.
- Test WD before starting, WD after one hole, WD after making the cut, and DQ after rounds 2, 3, and 4.
- Confirm incomplete rounds are never stored as full rounds and that a later complete record replaces—not duplicates or fails to update—an earlier record.
- Confirm validation never ranks a three-round DQ total against four-round finishers.

### 6. Simulation invariants and settlement economics

Use deterministic/property tests across pre-tournament and in-play simulators.

For randomized fields and extreme inputs, verify:

- all probabilities are finite and within `[0,1]`;
- win probability sums to one after fractional tie credit;
- expected top-5/10/20 occupancy is economically correct at boundary ties;
- `win <= top5 <= top10 <= top20 <= cut` before calibration, after calibration, and after market blending;
- matchup and 2-/3-ball probabilities plus tie mass are coherent;
- permutation invariance;
- reproducibility under a fixed seed;
- no-cut make-cut probability is exactly one and the cut market is suppressed;
- both missed-cut matchup players settle by their 36-hole scores;
- dead-heat, push, and loss rules use the recorded settlement rule;
- stake/EV calculations match a hand calculation for two-way and three-way ties.

Explicitly test two- and three-way ties for first, top-5 boundary ties, matchup pushes, and 3-ball shared minima. Check that fractional credit is not applied twice between simulation and EV calculation.

### 7. Pre-tournament versus in-play consistency

- At zero completed rounds and identical configuration/seed, compare every market and require agreement within exact equality or justified Monte Carlo tolerance.
- After round 1, verify the upcoming 36-hole cut is simulated rather than treating everyone as through.
- After round 2, verify cut players cannot re-enter and survivors are not cut again.
- Verify the same correlation, tail, weather, major, no-cut, cut-rule, and total-round settings reach both simulators.
- Confirm the separate win regime remains coherent with place probabilities.
- Confirm pre-tournament calibration is disabled in-play unless a separately validated in-play map is explicitly supplied.
- Look for discontinuities caused solely by switching engines rather than observed scores.

### 8. Market de-vigging, blending, and staking

- Recompute representative outright, top-N, cut, matchup, and 3-ball bets from raw odds through de-vig, calibration, blend, EV, Kelly, caps, rounding, and recommendation.
- Test complete and partial outright boards whose implied sums are below, at, and above the old `1.10` threshold.
- Verify completeness is based on credible field coverage and cannot be fooled by duplicates or unmatched players.
- Confirm different market blend weights cannot break nesting.
- Confirm matchup pushes use conditional win probability and correct Kelly math.
- Confirm 3-ball dead-heat-equivalent probabilities are not treated as exclusive-win probabilities.
- Test caps for one golfer's nested bets, all outright winners, both sides of one matchup, every member of a 3-ball, repeated/aliased group IDs, and many bets sharing one weather wave.
- Confirm penny rounding cannot breach player, group, or total caps.
- Do not describe the code as joint/simultaneous Kelly unless it actually optimizes a joint return distribution.

### 9. Identity, persistence, and reports

- Construct two distinct golfers with the same display name but different provider IDs and confirm SQLite, field entries, odds, history, and results do not merge them.
- Construct folded-name collisions and confirm resolution becomes explicit/ambiguous rather than selecting one silently.
- Verify every normalizer handles `Højgaard`, `Åberg`, `Fdez-Castaño`, initials, punctuation, and suffixes consistently.
- Check that ambiguous/unresolved players cannot be staked and cannot silently receive another player's prior.
- Interrupt primary CSV/JSON/report writes and verify readers see either the old complete file or the new complete file, never a truncated artifact.
- Verify `weekly_report --edge` persists and reads the same newly computed edge result.
- Confirm an empty or refused board clears stale edge and round reports.

### 10. CLV integrity

- Confirm accepted event-tagged prices actually call the snapshot path.
- Verify top-N and cut lines are de-vigged individually rather than normalized across golfers.
- Confirm event is mandatory for snapshots and lookups.
- Test duplicates, mixed events, timezones, snapshots after event start, settlement-time snapshots, and a future timestamp.
- Determine whether the implementation can genuinely identify a pre-start closing price. If not, flag any remaining use of the word `closing` or `CLV` as unsupported.
- Confirm no test or failed edge run pollutes production odds history.
